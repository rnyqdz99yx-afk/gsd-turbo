> [!WARNING]
> **Бета.** gsd-turbo молодой: по-настоящему его гоняли на одном проекте и на Windows. Фоновые сессии работают **без запросов разрешений** (`bypassPermissions`) и тратят лимиты вашей подписки Claude заметно быстрее обычного GSD. Прочитайте [Перед началом](#перед-началом).

## Что он делает

`/gsd-autonomous` ведёт майлстоун внутри одной сессии Claude Code: останавливается, когда кончается контекст, ждёт вас на каждом решении и снова и снова гоняет полный набор тестов. gsd-turbo отдаёт майлстоун маленькому процессу-супервизору:

| | Обычный GSD | gsd-turbo |
|---|---|---|
| Где идёт фаза | в вашей сессии | в фоновой сессии; свою можно закрыть |
| Кончился контекст | вы делаете `/clear` и запускаете заново | новая сессия продолжает с того же шага |
| Решения | спрашивает вас каждый раз | берёт рекомендованный вариант и записывает его |
| Чекпоинты планов | ждут вас в момент остановки | вопросы-кнопки, на которые можно ответить **заранее**: в сессии, в панели или в Telegram |
| Проверки качества | одна за другой | параллельно |
| Тесты | полный набор после каждой волны | только тесты, которые задевает изменение; один полный прогон на фазу |
| Проверки `human_needed` | все ваши | браузерные и HTTP-проверки проходит агент `turbo-uat`; вам остаётся только то, что можете сделать лишь вы |
| Следующая фаза | запускаете вы | стартует сама |

## Как это устроено

```text
супервизор turbo-run (обычный Node, без LLM)
 ├─ фаза N  → фоновая сессия Claude Code с /turbo-phase
 │             свежесть → обсуждение → план → выполнение → проверки ∥ → исправления → все тесты → UAT → готово
 ├─ контекст кончился? → новая сессия продолжает с того же шага
 ├─ нужен владелец?    → карточка с вопросом в сессии, в панели, в Telegram; уведомление на рабочий стол
 └─ фаза готова        → push + CI (по желанию) → следующая фаза
```

Сам GSD он не меняет: работает с ним только через `gsd-tools` и его собственные скиллы, агенты и сценарии.

## Быстрый старт

Нужны Node.js ≥ 20, git, Claude Code ≥ 2.1.290 и GSD core 1.16.x или 1.17.x (`npx @opengsd/gsd-core@1.17`).

```bash
# 1. Установка (копирует файлы в ~/.claude; --dry-run покажет, что будет сделано)
git clone https://github.com/rnyqdz99yx-afk/gsd-turbo && cd gsd-turbo && node install.mjs

# 2. Один раз откройте свой GSD-проект и подтвердите доверие к папке
cd /путь/к/вашему-gsd-проекту && claude
```

```text
# 3. В этой сессии Claude Code
/turbo-autonomous
```

Всё. Ход прогона виден справа в любой сессии Claude Code в этом проекте (если окно слишком узкое для панели, наберите `/turbo-view`). Сессию можно закрыть: супервизор продолжит работу и пришлёт уведомление, когда понадобитесь вы или когда майлстоун будет готов.

| Команда | Что делает |
|---|---|
| `/turbo-autonomous` | запустить остаток майлстоуна (`--only N`, `--from N --to M`, `--all`) |
| `/turbo-autonomous status` | что идёт сейчас и что ждёт вас |
| `/turbo-autonomous answer` | ответить на открытые вопросы |
| `/turbo-autonomous away` | заранее ответить на всё, на что можно, и уйти; `back` покажет, что произошло |
| `/turbo-autonomous attend N` | довести фазу N здесь, вместе с вами (для планов, где нужно устройство, вход в аккаунт…) |
| `/turbo-autonomous stop` | остановить супервизор и его сессии |
| `/turbo-adopt` | перевести на turbo майлстоун, который уже идёт на обычном GSD: где он стоит, какие закрытые фазы turbo пропускает, все вопросы сразу, один коммит; затем `/turbo-autonomous` ([подробно](docs/reference.md#adopting-a-running-milestone)) |

## Перед началом

- **Разрешения.** Фоновые сессии запускаются с `--permission-mode bypassPermissions`, чтобы никому не приходилось подтверждать вызовы инструментов. Ваши хуки Claude Code при этом работают. Для первого прогона построже задайте `lane_permission_mode` в `.planning/turbo/config.json` ([настройки](docs/reference.md#config)).
- **Расход.** Фазы идут на вашей модели в фоне, с параллельными помощниками и автоматическим UAT. Лимиты подписки закончатся быстрее, чем с обычным GSD.
- **Версия GSD.** Проверено с GSD core 1.16.x и 1.17.x. С другой версией `turbo-run doctor` переходит в безопасный режим, а если GSD изменился несовместимо — отказывается запускаться.
- **Что остаётся за вами.** Подписи, ваши аккаунты на сторонних сайтах, физические устройства, 2FA, деньги. Всё остальное прогон сделает сам, а потом остановится и спросит. Безопасный вопрос, оставленный без ответа на час (рекомендованный планом вариант, проверка, которую решают автоматические доказательства), turbo решит сам и сообщит об этом вместе с командой отмены ([какие именно](docs/reference.md#owner-questions)).
- **Предохранители.** Без force-push, без переписывания опубликованной истории, без удаления данных без пробного прогона (dry run), без перезаписи запущенного исполняемого файла. Подробности в разделе [Safety](docs/reference.md#safety).
- **Удаление:** `node install.mjs --uninstall` ([что проверить сначала](docs/reference.md#uninstall)).

## По желанию

- **Telegram**: вопросы приходят в Telegram, отвечать можно кнопками вдали от компьютера ([настройка](docs/reference.md#telegram-optional)).
- **Push и CI**: супервизор пушит и следит за GitHub Actions; упавший прогон возвращается в фазу на исправление ([настройка](docs/reference.md#push-and-ci-optional)).
- **Точечные тесты**: их включает `turbo-run init`, если известна команда полного прогона ([как он решает](docs/reference.md#what-happens)).
- **Автозапуск после перезагрузки**: `turbo-run autostart on` поднимает супервизор этого проекта при входе в систему, если прогон шёл; `off` всё убирает ([что он настраивает](docs/reference.md#after-a-crash-or-a-reboot)).
- **Облегчённый режим**: включён по умолчанию (`lean.enabled`): облегчённые настройки GSD, меньше усилия у планировщика GSD и у сессий полос, бюджет STATE.md; `turbo-run lean status` показывает его, `turbo-run lean off` возвращает настройки GSD ([что он меняет](docs/reference.md#lean-mode)).

## Если что-то пошло не так

**После сбоя или перезагрузки.** Вернуться в свой чат: `claude -r` (выбрать по названию) или `claude --resume <id>` — эту строку с id печатает `/turbo-autonomous status`. Голый `claude -c` открывает последний разговор в папке, а в режиме checkout это может быть разговор полосы. Панель turbo возвращается сама. Если автозапуск не включён, снова запустите супервизор через `/turbo-autonomous`: полосы, чьи сессии погибли вместе с машиной, продолжат с того места, где остановились ([подробнее](docs/reference.md#after-a-crash-or-a-reboot)). Если супервизор молча остановится, пока вас нет, turbo один раз скажет об этом на рабочем столе и в Telegram: это сделает панель turbo в вашей сессии или работающая полоса.

## Дорожная карта

1. ✅ **Ядро**: супервизор, автоматическое продолжение, точечные тесты, безопасный режим.
2. ✅ **Быстрые фазы**: `/turbo-phase` с параллельным прологом, проверки параллельно, `turbo-uat`.
3. ✅ **Владелец в цикле**: карточки вопросов с ответом заранее (сессия, панель, Telegram), push и CI, живая панель, живые сессии с фазой.
4. ✅ **Параллельные фазы**: `/turbo-plan-milestone` заранее готовит все будущие фазы разом; несколько фаз идут одновременно, с блокировками общих ресурсов и слиянием.
5. ✅ **Подключение к идущему проекту**: `/turbo-adopt` подключает turbo к майлстоуну, который уже в работе: где он стоит, что пропущено, все вопросы сразу, план на остаток.
6. **Лёгкий turbo**: ✅ облегчённый профиль GSD — без проверок, которые ничего не ловят, меньше рассуждений и чтения, один проход фиксера, один полный прогон тестов на фазу, `turbo-run cost` *(v0.5.x, текущая)*; сборочный путь — фазой дирижирует код, и каждый план стартует в своей короткой сессии, как только слиты нужные ему планы *(v0.6, в работе)*.
