# gsd-turbo v0.3.2 · scan-tmp — push-scan false alarms and the lane temp directory

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. TDD: each task's test first, run it red, commit it (`test: ...`), then the fix (`fix: ...`).

**Goal:** (a) the push scan stops refusing plain prose such as a test verdict `PASS: dry-run complete` or `the tests pass: ...`, still catches real credential assignments, and the owner can clear a reviewed false alarm with one command; (c) a lane's temp directory lives outside the project checkout, so a project test that checks that `os.tmpdir()` lies outside the checkout passes inside a lane too.

**Source:** the second live run of v0.3.1 (two pushes refused for prose `pass:` / `PASS:`, each forcing a rewrite of unpublished history; a project's own tests red in every lane run because TMP pointed into `.git/turbo/tmp/...`).

**Tech stack:** Node >= 20, ESM, zero dependencies, `node:test`. Windows and Linux.

## Global constraints

- Public repository: generic examples only; token-shaped test values are built at run time.
- Only the targeted test files of a task are run (`node --test test/<file>.test.mjs`), never the full suite.
- No version bump, tag, push or merge here.
- `lib/state-sync.mjs` and `lib/uat*.mjs` are changed by other branches: not touched (the shared rule in `lib/secrets.mjs` reaches the UAT scan by import, unchanged code there).

## Decisions

- **The rule, not a per-project switch.** `credential assignment` keeps its name and its kinds of keys, with three changes:
  1. A bare `pass` is a key only when it is quoted (`"pass": ...`, `'pass' = ...`), written right before `=` (`pass=...`), or the last part of an identifier (`DB_PASS: ...`, `smtp_pass=...`). Prose `pass:` / `PASS:` / `tests pass: ...` no longer matches.
  2. Identifier-shaped keys are caught too: `DB_PASSWORD=`, `GITHUB_TOKEN=`, `client.secret:`, `my-api-key:` (before, `\b` hid a key after `_`).
  3. Everything else as before: `password`, `passwd`, `pwd`, `secret`, `token`, `api_key` / `api-key` / `apikey`, then `:` or `=`, then a value of 6+ characters without spaces or quotes.
- **A reviewed false alarm is cleared by fingerprint, never by file or kind.** A fingerprint is the first 16 hex characters of sha256 over `<file> NUL <rule> NUL <added line>` (a commit message line: file `(commit message)`, so a rewritten commit keeps it). It ties the clearance to that exact line: a new secret in the same file is still refused. Only secret-rule hits have fingerprints; a forbidden file name, an unreadable name and a Git LFS pointer can never be cleared this way (the owner still pushes those by hand).
- **Where:** `.planning/turbo/run/push-allow.txt`, one fingerprint per line, `#` comments: in the git-ignored run directory, so clearing a false alarm never needs a commit and the list is never pushed. Fingerprints are kept in the refused push record (`p<N>-push.json`, field `allowable`), never in a notification.
- **How:** `turbo-run push-allow <phase>` adds every fingerprint of the phase's last refusal to the file and prints what it cleared (file + kind) and what it cannot clear. It refuses inside a lane (`TURBO_LANE`): a lane never clears its own findings. The supervisor scans a refused request again when the allow file changed since the refusal (the record keeps a hash of the file as it read it), so the owner's one command is enough: the push goes out at the next tick if nothing else is found.
- **The lane temp directory** moves from the git directory to turbo's own state directory: `<Claude config dir>/turbo/tmp/<project key>/p<N>` (`~/.claude/turbo/tmp/...`, honours `CLAUDE_CONFIG_DIR`), the same for a repository and a plain directory. Not the system temp directory: the lane rule "never /tmp or the system temp directory" and the cleanup stay as they are. The link checks keep working with turbo's directory as the anchor (created before the check). No git call any more.

## Fix round 1 (review)

- The credential rule also counts a bare `pass` where config puts it: a quoted value, a spaced `=`, lowercase after indentation, `.`, `{`, `,` or a YAML `- `, and `pass:x1y2z3` (a letter and a digit, no space). Prose stays silent.
- `push-allow` is bound to one refusal: the supervisor records an 8-hex refusal id (the pushed sha and the fingerprint set) and, per fingerprint, commit, file and line. `push-allow <N>` lists them and writes nothing; `push-allow <N> <refusal>` allows exactly those lines and refuses any other id. A refusal whose fingerprint set changed is notified again. The supervisor logs and notifies (`pushAllowed`) how many lines an allow-file change covers.
- The allow file moves out of the checkout: `<Claude config dir>/turbo/allow/<16-hex project key>.txt`; the lane rule forbids writing it.
- The lane temp directory is keyed by 16 hex; a config directory inside the project moves it to `<system temp>/gsd-turbo/tmp/<key>`, logged.
