# gsd-turbo v0.3.2 — `state-sync` keeps the owner's words in STATE.md

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `turbo-run state-sync N` writes only the position fields it owns in `.planning/STATE.md` and never replaces the `Status:` / `Last activity:` text the owner or a controller wrote; and when GSD's `begin-phase` reset the position of a phase whose plans all have a SUMMARY, `state-sync` puts the position and the text back.

**Why (from the second combat run of 0.3.1):**
- A lane's stop ran `state-sync`: it replaced the whole `Status:` line of Current Position with `Executing Phase <N>` and `Last activity:` with `<date> — Phase <N> stopped; next plan <id>`. The owner's ruling and the release facts written there were gone; it happened twice in one run.
- GSD's own `state.begin-phase` rewrites the same two lines on every execute-phase run (first run and resume alike). A final-gate re-run of execute-phase on a phase with every plan summarized reset `Plan` to `1 of <total>` and `Status` to `Executing Phase <N>`; `state-sync` then said "left as it is (every plan has a summary)", and the lane had to revert STATE.md by hand.

**Base:** `main` at `9e7dc7a` (0.3.1). Code: `lib/state-sync.mjs` (`stateSync`), its output line in `lib/cli-phase.mjs` (`syncState`), tests `test/state-sync.test.mjs`.

## GSD 1.16 facts this plan relies on (read in `state-transition.cjs`, `state-document.cjs`, and tried on a scratch repository)

- **G1** `begin-phase` takes its resume branch (keeps `Plan`) when the `Status` value contains `Executing Phase\s+<token>\b` anywhere (unanchored, case-insensitive). Both `<text> (Executing Phase 05)` and `Executing Phase 05 — <text>` keep the plan.
- **G2** `begin-phase` always writes `Status: Executing Phase <token>` (both branches) and `Last activity: <date> — Phase <token> execution started` (first run) or `… execution resumed (wave continue)` (resume). The first run also writes `Phase: <token> (<name>) — EXECUTING`, `Plan: 1 of <count>`, `Current Plan: 1`.
- **G3** `advance-plan` and `planned-phase` replace `Status` only when it is a GSD value: a known default, or a value that *starts with* `Executing Phase <n>` (`KNOWN_STATUS_PATTERNS`, anchored at the start only). Text that starts with the owner's words is kept.

## Decisions

- **D1 Owned fields.** `Phase`, `Plan`, `Current Plan`, `Total Plans in Phase` (inside Current Position, as before) and the session block that `state record-session` writes. `Last activity` is never sent.
- **D2 Status.** When the `Status` value already contains `Executing Phase <N>` it is not sent. When it is empty or a GSD value (G3's list, kept small in `lib/state-sync.mjs`), it becomes `Executing Phase <N>`. Otherwise the owner's text stays first and the marker goes at its end: `<text> (Executing Phase <N>)` (an earlier marker for another phase is dropped first). The marker is at the end so that `advance-plan` and `planned-phase` keep the text (G3), and begin-phase still resumes (G1).
- **D3 Text begin-phase replaced.** `Status` that reads exactly `Executing Phase <token>`, and `Last activity` that reads a bare date, `<date> — Phase <token> execution started`, `… execution resumed (wave continue)` or `… stopped; next plan <id>` (what `state-sync` up to 0.3.1 wrote), are marks of GSD (or of the old `state-sync`), not the owner's words. When a mark is present, `state-sync` looks through the last 50 commits of STATE.md, newest first, for the first one whose Current Position carries no mark, and takes the owner's text for the marked fields from it. Without such a commit the fields stay as they are.
- **D4 Every plan summarized.** When the `Status` mark of begin-phase is present, `state-sync` puts back the position: `Plan: <total> of <total>` when its number is not the total, `Current Plan: <total>`, and `Phase`, `Status`, `Last activity` from the commit of D3 where they differ. It does not record a session (begin-phase does not touch it) and commits with `docs(phase-<N>): put back the STATE.md position that begin-phase reset`. Without the mark it changes nothing, as before.
- **D5** Best effort, the same as before: any failure puts STATE.md back to the bytes it had and prints a `warn:` line; exit 0.
