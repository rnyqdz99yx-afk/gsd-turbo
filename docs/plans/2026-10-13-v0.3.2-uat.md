# gsd-turbo v0.3.2 — UAT: owner-ruled rows are deferred follow-ups; a stale report after UAT re-runs only the verifier

**Goal.** Two fixes from the second live run:

- **(d)** A UAT row that is `skipped` or `blocked` and whose reason carries an owner ruling ("owner ruling …", "DEFERRED → Phase N", "отложить …") is a deferred follow-up, not something to test again. turbo rewrites it to GSD's deferral template (`result: skipped`, `reason: "Deferred follow-up: <the reason, unchanged>"`, an entry in `## Deferred Follow-Ups`), so `gsd-tools phase uat-passed N --uat-only` passes. A skipped or blocked row without a ruling still makes the phase wait, but the owner text says plainly that nothing must be tested again and names the one command that confirms the deferral.
- **(e)** Any UAT write after verification makes `VERIFICATION.md` `stale` (the UAT file is in the report's `covered_files`). When nothing outside `.planning/` changed since the report's commit, the lane re-runs only GSD's verifier (the last code review and the green test and CI runs still hold); when code changed, the full chain stays.

**Contract with GSD (1.16).** `uat-predicate.cjs`: a skipped row passes when its first reason line matches `/^["']?deferred follow-up\b/i`; the `## Deferred Follow-Ups` list (`test`, `idea`, `deferred_at`) is the durable record. `verify-work.md` `complete_session`: `uat.complete-session` writes and commits only on a material change; a `stale` report routes to `execute-phase/steps/verify-phase-goal.md` (hooks, code review, regression gate, verifier).

## Decisions

- **D1** Detection is a strict whitelist of one unambiguous form (`ownerRuling`, after review rounds 1–3); a miss is cheap, because the row goes to the owner, who confirms it with one `uat defer N <numbers>`. All must hold: one clause (split on `; . ! ? — ,`) holds a dated ruling (`owner ruling <YYYY-MM-DD>`, `решение владельца (от) <YYYY-MM-DD>`, `по решению владельца <YYYY-MM-DD>`, the date right after the marker) and a deferral to a numbered phase (`defer… to Phase N`, `DEFERRED → Phase N` / `-> Phase N`, `Отложить … на фазу N / на Phase N`); no `?` anywhere; no stop word (pending, awaiting, required, needs, wait…, ask, expected, TBD, until, n't, never, now, not, no, without, revoked, overturned, superseded, against, rather, instead, unless, if, only, draft, maybe, reject…, rescind…, cancel…, "test in this phase", ждём, нужно, требуется, пока, нельзя, нет, без, не, сейчас, отмен…, если, проверить; and since the final review withdraw…, revers…, retract…, replac…, propos…, would, decision, отозван…, предлага…, под вопросом, пересмотр…, отклон…) from the ruling clause to the end, nor in an earlier clause, except an earlier clause that is only the plain precondition `no <noun> …` / `нет <noun> …` whose noun is not way, deferral, ruling or decision (решение, отсрочка, способ); and exactly one dated ruling in the whole reason (a second one may replace or reverse the first). An undated ruling, or one that defers without a phase number ("tester steps afterwards"), goes to the owner's confirm list.
- **D2** `turbo-run uat defer N --rulings` rewrites the detected rows; `turbo-run uat defer N <n>[,<n>…]` rewrites the rows the owner names (only `skipped` or `blocked` rows; pass, issue and pending rows are refused). The reason text is kept verbatim after the prefix. An existing `## Deferred Follow-Ups` entry for the test that turbo did not write is left alone and none is added next to it; turbo's own entries carry `source: turbo-uat`.
- **D3** `ownerRequest` keeps `needsOwner` and `counts.signoff` (every row the phase waits on) and adds `counts.confirm`: the skipped or blocked rows among them. They get their own section and reason: "nothing to test again — confirm that the items stay deferred: …". A real button for it in the pane and Telegram needs an owner question without a waiting agent; that is left open.
- **D4** `turbo-run staleness N --verification [--json]` reports `route`: `verifier-only` when the phase's VERIFICATION.md is committed and every path changed since its last commit (committed, staged, unstaged, untracked) lies under `.planning/`; `full` otherwise (no report, report never committed, any other path changed). It also names `since`, the changed code paths and the last REVIEW.md commit for the step's note. After review: a code change between the last REVIEW.md commit and `since`, or no REVIEW.md commit while GSD's `workflow.code_review` is on (its default; while turbo has the gates off, the value saved in `.planning/turbo/gates/p<N>.json` decides), also gives `full`; `verifier-only` carries a `note` that the regression gate and the code review were not re-run.
- **D5** `/turbo-phase` gets one procedure, **Stale report**: `verifier-only` → only the `verifier_dispatch` Agent call of GSD's `verify-phase-goal.md`, then commit the report; `full` → `gsd-execute-phase N --no-transition`. Used at `uat` point 1, before verify-work at `uat` point 5 (after `uat.complete-session`, so verify-work finds nothing to write and the fresh report is not staled again), and at `close` point 2.

## Tasks (tests first)

1. `test/uat-defer.test.mjs` (new): rulings detected in English and Russian; rows without a ruling, pass/issue/pending rows and already-deferred rows untouched; the rewritten rows satisfy GSD's deferral regex; the Deferred Follow-Ups entry is written once (idempotent) and never next to a foreign entry; counts recounted. `ownerRequest`: `counts.confirm`, the plain section and reason in both languages, never a re-test wording.
2. `test/cli-uat.test.mjs`: `uat defer N --rulings` and `uat defer N 7,8` through the CLI; a refused row number exits 1 and changes nothing.
3. `test/staleness.test.mjs`: `verificationRoute` — planning-only change → `verifier-only`; a code change (committed, unstaged or untracked) → `full` with the path; no report / uncommitted report → `full`. CLI `staleness N --verification --json`.
4. `test/skill-turbo-phase.test.mjs`: the **Stale report** procedure and its use in `uat` and `close`; `uat defer N --rulings` before owner-request; `uat.complete-session` before verify-work.

Only the targeted test files run; CI runs the whole suite after the push.
