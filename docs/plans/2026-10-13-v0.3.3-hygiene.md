# gsd-turbo v0.3.3 — hygiene: a push already on the remote, a clean resume, one verifier pass after UAT

**Goal.** Four fixes from the third live run:

- **(a)** A queued push request whose sha is already on the remote branch (pushed by hand since the request) ends as «already pushed», not «diverged»: the request is answered, the lane's `--wait` gets an exit-0 line, the owner is not notified.
- **(b)** `resume N` (with or without `--start`) clears the phase's owner request (`run/p<N>-owner.md`): the resume is the owner's answer to it. `status` never presents the lane of a previous supervisor run as the current one: while a resumed lane waits for its relaunch, status says so instead of `watch: claude attach <old session>`.
- **(c)** One verifier pass per UAT step. In the run, the close re-ran the verifier-only re-verify three times. Root cause: GSD's `uat.complete-session` compares the working UAT file with its blob at `HEAD` byte for byte (only `updated:` excluded). In a checkout with `core.autocrlf=true` the working copy has CRLF and the blob LF, so every call is a «material change»: it writes a new `updated:`, commits, and stales `VERIFICATION.md` again (the lane's call, then verify-work's own call). Reproduced with gsd-core 1.16 in a scratch repository: a CRLF working copy commits on every call; the same file with LF line endings is a no-op. In addition, uat point 1 refreshed a stale report before turbo-uat's records staled it again.
- **(d)** A lane must never revert a legitimate edit to a covered file only to keep the report fresh: with the verifier-only route (v0.3.2) a `.planning`-only change costs one verifier run.

## Decisions

- **D1** After the fetch, a remote branch that is not an ancestor of the requested sha, while the sha is an ancestor of the remote branch, is «already pushed». The record keeps outcome `pushed` with `already: true`; nothing is scanned or pushed, nothing is notified, no CI watch starts, and `lastPush` (turbo's own last push and its CI watch) is carried over unchanged. `describeRecord` answers `already pushed: <sha> is on <remote>/<branch>; nothing to push` with exit 0. `requestPush` keeps the request for the same head, as after a push. Not a new outcome: the live view (`lib/view.mjs` `PUSH_OUTCOMES`, the pane's push mark) treats any outcome other than `pushed` as a failed push, and those files belong to the pane rework of this release.
- **D2** `resumePhase` (`resume N`, `resume N --start`, `attend N --done`) removes `run/p<N>-owner.md`. It keeps `p<N>-owner.notified`, so the same checklist is not sent again. Whatever is still open comes back: step **uat** writes the file again with `turbo-run uat owner-request N`, and step **close** now runs `owner-request` before its done record, so a checklist of deferred live checks is current when the phase closes after a resume.
- **D3** `printStatus` (status, and start's «already running»): a lane with `forceRelaunch` prints `lane: phase N · relaunch pending (resume) · replaces session <id> at the supervisor's next check · mode …`, and no `watch:` line. `--json` is unchanged (it already carries `forceRelaunch`). The pane reads the same supervisor file; whether it shows the pending relaunch is left to the pane rework (noted for the controller).
- **D4** `turbo-run uat settle N [--json]`: when the working UAT file has CRLF line endings and its blob at `HEAD` has none, it rewrites the working file with LF line endings; when the file then equals the blob byte for byte, it runs `git add` on that path only, so git's index sees the file clean (nothing is staged: the blob is the same). A file not committed yet, or a blob with CRLF, is left alone. After it, `uat.complete-session` writes only on a real change, and the file it writes keeps LF, so verify-work's own complete-session finds nothing to write either. turbo does not change GSD (the comparison is GSD's; reported upstream by the controller if wanted).
- **D5** `verificationRoute` also names `reported`: the `status` the report's frontmatter holds (`human_needed`, `passed`, …; null when unreadable). Step **uat** point 1: `stale` with route `verifier-only` and `reported` `human_needed` goes on as `human_needed` without a refresh; the one **Stale report** comes at point 5, after every UAT write of the step (turbo-uat's records, `uat defer`, `uat settle`, `uat.complete-session`). Any other `stale` keeps the refresh at point 1 (code changed, or the report said something else).
- **D6** **Stale report** gets two rules: one pass per pass through the uat step unless code changed (a report stale again after it names the late write in the note, then runs once more), and never revert or hold back a legitimate edit to a covered file to keep the report fresh: keep the commit; a `.planning`-only change goes through **Stale report** on the `verifier-only` route.

## Changelog notes

- A push request for a commit someone already pushed answers «already pushed» (exit 0), with no owner notification.
- `resume N` clears the phase's owner request; status shows a resumed lane as a pending relaunch.
- `turbo-run uat settle N` and the uat step's order give one verifier pass after UAT in CRLF checkouts too.

## Review round 1

- `verificationRoute` names `uatOnly`: only the phase's UAT file, STATE.md and `.planning/turbo/run/` changed. uat point 1 waits for point 5 only then; a changed plan, context or roadmap refreshes the report first. Point 5 reads the refreshed report again: `passed` or covered `human_needed` → verify-work; a human item without a UAT row → back to point 2 once (the row added as `[pending]`, committed), a second time stops for the owner; anything else, `gaps_found` included → fail.
- `uat settle` no longer runs `git add` (a staged version stays, `core.safecrlf` cannot fail it). Measured with `core.autocrlf=true`: an LF working copy of an LF blob still shows as modified in `git status` until git refreshes its index (`git diff` is empty); GSD's comparison reads bytes, so complete-session is a no-op either way.
- A remote branch already at the requested commit is «already pushed» too (no empty push, no new CI watch, no other phase's watch superseded); its CI is not watched (README).
- Step **close** writes the owner request before every stop for the owner; status names `turbo-run start` for a resumed lane while no supervisor runs; a BOM before the report's frontmatter is skipped.
