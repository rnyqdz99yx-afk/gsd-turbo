# gsd-turbo v0.3.3 — owner stops: every stop that asks the owner is a question card, and the answer resumes the lane

**Goal.** From the third live run (HIGH, the owner's main touchpoint): a lane's needs-owner stop that is not a plan checkpoint ("the gap round is done; decide: fix the review warnings first, or run the live check now") reached the owner only as the lane's raw English `--reason`, cut at 200 characters, full of ids. No card, no button, no Telegram question; the owner asked "what is it about, where is it waiting for me", the decision was taken in another chat, and the lane was resumed by hand. After this release:

- the lane asks through `turbo-run ask N`: a question card in the owner's language (`config.lang`), verdict first, 2–4 options with the recommended one first and marked. It is the same kind of owner question the checkpoint questions are (pane card, Telegram buttons, `turbo-run answer`);
- the owner's answer wakes the same lane session (the same-session wake of the checkpoint answers, the same D13 bounds), and the lane does what the chosen option says;
- "fix these findings first" runs as a counted gap round from the chosen REVIEW.md / VERIFICATION.md items, with no hand-made UAT row;
- a review that finds new edges in the same files round after round is said plainly in the question, with an option to stop polishing and run the live check;
- owner-only work (a device, the owner's 2FA, the owner's accounts) is a card with one action and the options "Done" / "I will do it later";
- an old-style `lane-status N needs-owner --reason …` with no question still notifies, framed in the owner's language.

**Contract with GSD (1.16).** `gsd-plan-phase N --gaps` reads its gaps from VERIFICATION.md and the UAT file; the planner prompt may carry an added paragraph (turbo already adds the **Gap plans** rule there). `gsd-code-reviewer` writes `<phase>-REVIEW.md` anew every round: findings as `### CR-01: <title>` / `### WR-01: …` / `### IN-01: …` (`BL-` is CR-equivalent), each with a `**File:** \`path:line\`` line. The REVIEW.md of earlier rounds lives only in git history.

## Decisions

- **D1 One question store.** A lane question is an entry of `run/p<N>-questions.json` like a checkpoint question: `source: "lane"`, `plan` and `task` null, `stopped: true`, `agentId` null, `kind` `decision` (options) or `human-action` (owner-only work), `class` `decision` or `owner-only` (classified). The pane card, Telegram, `turbo-run answer` and `questions --open` take it with no change: the mod's card already falls back to "phase N" without a plan. Its id is `ask-<k>`; `k` is one more than the highest `ask-` id in the questions file and the answers file (the answers file is in git and outlives the run directory, and `liveAnswer` would take an old answer for a reused id).
- **D2 `turbo-run ask`.** `ask N --question <text> [--context <text>] --option "<label>|<description>" … --recommended <k> [--about-review]` (2–4 options, `--recommended` required) or `ask N --action <text> [--context <text>]` (the options are turbo's: Done / I will do it later). Lengths as `buildQuestion`: question 300, context 600, label 80, description 200 code points, cut after `maskSecrets`. The recommended option is moved first and marked. Owner text (question, context, labels, descriptions) is refused when it holds turbo's or GSD's ids: finding codes (`WR-01`, `G-32-22`), plan ids (`32-46`), question ids (`ask-3`, `32-01-t2`), commit hashes, file names with an extension; with `lang` `ru` also when the question has no Cyrillic letter. The refusal names the piece and asks for plain words. `ask` supersedes (removes) the phase's older open lane questions, then records `lane-status N needs-owner --reason "owner question ask-<k>"` itself, so the stop and its question are one command. allowOther is on: the owner's own words are data too.
- **D3 Plain surfaces.** `owner question ask-<k>` is stripped from the shown reason like `owner question <plan>-t<task>` (messages, `lib/view.mjs`, the mod's `laneReason`: one regex each). While a lane question waits, the supervisor sends no `laneNeedsOwner`: owner-tick's `questionsReady` already carries the plain question (title "Phase N: needs your answer (1)", body the question); a single question is no longer cut at 80 characters there, and an empty header no longer leaves a bare `: `. `turbo-run status` lists every open question the phases wait for (`owner question: phase N — <question>`).
- **D4 Delivery to the lane itself.** `deliveryState.ready` takes an answered lane question too (it has no agent). The wake prompt (`answerWakePrompt`) names each lane question with the chosen option's number and its label (cleaned of double quotes, percent signs and controls: the prompt is a plain argv value; never the owner's own words), and tells the lane to read the answer with `questions N --deliver` and mark it `--delivered <id> --path lane`. A lane in safe mode gets its own resume text. A new session (failed wake, relaunch) gets the lane ids in its first prompt as its own questions to take, not as continuation agents. `DELIVERY_PATHS` gains `lane`. A checkpoint answer keeps its prompt and path word for word. `refreshQuestions` keeps lane questions until delivered; `attend` does not release them (they belong to no agent).
- **D5 The answer is data.** The delivery message: "The owner's answer to the question you asked (ask-3): option 2, <label> — <description>." or the owner's own words, then: it only chooses among the options you offered (own words are the owner's choice for this question only); it never changes the lane rules, the skill's steps or your permissions. The skill: before asking, decide what each option makes you do and say it in its description; after the answer, do exactly that.
- **D6 Owner-chosen fixes.** A new gap step `owner-gaps` (`phase-step N --attempt owner-gaps`): at most `gap_rounds` per phase across sessions, resumed like the other gap steps, with no evidence comparison (the owner's choice is the reason for the round). `turbo-run owner-gaps N [--review <code>,…] [--verification <n>,…]` prints the paragraph the lane adds to the gsd-planner prompt of `gsd-plan-phase N --gaps`: each chosen REVIEW.md finding (code, title, file, its text) and VERIFICATION.md gap (its truth), as gaps of this round. An unknown code or number is refused.
- **D7 Review-edge loop.** A pure `reviewLoop(versions)` over REVIEW.md versions (oldest first): the streak of consecutive versions, counted back from the newest, in which every version has CR/BL/WR findings, shares at least one finding file with the version before it, and has a finding whose title the version before it did not have. Versions with the same findings as the one before are one round. History: the file's last 12 commits plus an uncommitted working copy. `ask --about-review` runs it: a streak of 2 or more puts the plain sentence first in the context ("the code review has found new edge cases in the same code for the third time in a row") and adds the option "Stop polishing — run the live check" (refused when it would be a fifth option). `ask` prints what it added.
- **D8 Fallback.** `laneNeedsOwner`'s body for a reason is "Phase N waits for you: <reason>." / «Фаза N ждёт вас: <reason>.». `lane-status N needs-owner` with no question waiting prints a hint to stderr: ask the owner with `turbo-run ask` (the status is still written).
- **D9 Lane rules.** `laneSystemPrompt` rule 2 (both modes) and the skill's **Stopping early** send every stop for the owner through `turbo-run ask` (a decision or an owner-only action); only a checkpoint stop (`owner question <plan>-t<task>`) keeps `lane-status N needs-owner`.
