# gsd-turbo v0.3.3 — the pane says what happens now, what comes next and when the owner is needed

**Goal.** The owner works in one window: their own Claude Code session in a turbo project is the turbo UI (the pane on the right, the band above the prompt, the question cards), Telegram when away. The third live run showed the pane as it is falls short of that:

- **w1** The pane opened by itself only in a terminal at least 144 columns wide; in a narrower one nothing said how to open it.
- **w2** `/turbo-autonomous` start did not tell the owner where to look.
- **u1** No "what is happening right now": `acceptance · 12 helpers finished` hid that the phase was fixing a red CI that minute.
- **u2** "Latest changes" listed raw English commit subjects with jargon (`docs(phase-32): …`, finding codes).
- **u3** No "what comes next / when will you be needed", although turbo knows the steps ahead and the owner touchpoints.
- **u5** About 90% of the pane empty: room for the phase's steps (done / now / ahead).
- **u4** (idea) `turbo-run status --watch` has no colour at all, so the fallback is a step down from the pane.

Everything owner-facing stays in the owner's language (`config.lang`, en and ru), plain words, verdict first, no ids, no jargon.

**Contract with the host (Claude Code 2.1.296, `$.ui.open` and `UiOpenResult` in the mod API types).** An open that answers the person's input ("asked": the hook of a command they typed, a prompt they entered, a Button, Input or Select they worked; never a timer, `session.start` or a queued prompt) is placed at any width: docked beside a fullscreen transcript from 110 columns, else inline above the prompt. An open the plugin makes on its own is placed from 144 columns (110 for an id the person opened before and has not closed by hand) and otherwise waits undrawn; the call resolves `{ isPlaced: false, reason }`. The pane turns placed when the person opens it or the terminal widens to the floor.

## Decisions

- **D1 (w1) Pane at any width, through the owner's own prompt.** The 144-column floor is the host's and holds for every open the mod makes on its clock: no mod can place a pane unasked in a narrower terminal. The mod keeps opening it by itself while the run is live (spec §7, D7 of S3) and now reads the result: `isPlaced: false` marks the pane as waiting. The next prompt the owner enters in that session opens it again from the mod's `prompt.submit` hook, which counts as asked, so it is placed at any width (docked from 110 columns in fullscreen, inline above the prompt below that). This happens once per module life and never after the owner closed the pane by hand (`ui.close` with origin `person`); the prompt itself is passed on unchanged. While the pane waits, the band adds one short phrase, `open the pane: /turbo-view` / `откройте панель: /turbo-view`, which disappears once the pane is placed (the mod asks `$.ui.panes()` on each read). What stays impossible: placing the pane in a narrow terminal before the owner's first prompt or command in the session.
- **D2 (u1) "Now" is derived, not recorded.** A pure function of the lane in the view (`currentAction`), first match: a red CI the running phase fixes itself (`fixing the red CI — attempt 1 of 2`, the last attempt said as such); the helpers at work by what they do, the most telling type first (fixer, debugger, reviewer, security auditor, test auditor, integration checker, verifier, acceptance tester, executors counted, planner, plan checker, researcher, any other as a count); a pending CI with no helper at work (`waiting for CI`); else the step itself in an active form (`running the final tests`, `wrapping up the phase`). Nothing for a lane that is not running or a supervisor that does not run: the lane line says that already. Drawn as the first line under the lane line: `Now: …`, amber while it fixes a red CI. The lane's own last tool call is not in the view and is not added (the transcript layer and the view contract stay as they are).
- **D3 (u2) Commits as a count by kind, no raw subjects.** A commit subject is the project's text in the project's language and conventions; turbo cannot translate it without a model, and a plain line per commit would be a guess. The pane and the text view show one line instead: `Latest changes: 2 fixes, 1 new feature · the last 12m ago`, the kinds read from the conventional-commit type (`feat`, `fix`, `test`, `docs`, `refactor`, anything else "other"), the largest count first. `turbo-run view --json` keeps the subjects for anyone who wants them. The verdict, "Now" and the steps already say what the work is about.
- **D4 (u3) "What comes next".** A section after the questions: the visible steps ahead joined with arrows, ending with `next phase` or, for the range's last phase, `end of the run`; then when the owner is needed, from what turbo already knows: a question the phase waits for, questions that can be answered ahead, a stop for the owner's decision without a question (the reason above says what), a failure, full mode, the last CI attempt (it asks next), and at the acceptance step still ahead or in progress the live checks that only the owner can do, if there are any. None of these: `Nothing needed from you now` in green. A lane that is done has no such section. The plain reason of a stop is said there in one line; the lane's raw reason line stays as it is (the owner-stop work turns those stops into question cards).
- **D5 (u5) The phase's steps.** A section `Phase steps:` listing the `/turbo-phase` steps in order, done (`✓`, dim), now (`▶ … — now`, bold; a stopped or held lane `■ … — stopped here`, red) and ahead (`·`, dim). `gates-off` and `restore` (turbo switching GSD's own gates) are left out unless the lane is at one of them. Derived from `lane.step` (STEPS is ordered and `completeStep` keeps it so), so a view without `done` still draws. The view model carries STEPS on its own (it imports nothing); a test holds it equal to `lib/phase-progress.mjs`.
- **D6 (u4) The text view keeps step with the pane, in colour on a terminal.** `formatView` draws the same new sections in plain lines (test/view.test.mjs keeps the pane's and the text's lines and words equal). `formatView(view, { color: true })` colours each line by its tone with ANSI SGR (green, amber, red, dim, bold), reset at the line's end, after the line is cleaned, so repository text never brings its own escapes. `status --watch` asks for colour when stdout is a TTY and `NO_COLOR` is unset (`useColor` in lib/watch.mjs); `view` without `--json` and every pipe stay plain.
- **D7 (w2) The start report says where to look.** `/turbo-autonomous` start, point 7, says once, in the owner's language: the run shows live in this session (and every Claude Code session of the project) in the turbo pane on the right and the line above the prompt, questions as buttons; `/turbo-view` opens the pane when it is not on screen; away from the computer, Telegram brings the questions when it is set up; without the mod, `turbo-run status --watch`.
- **D8 (coordination)** Question cards, the verdict, the band's verdict part and the lane's reason line are not changed (owner-stop and hygiene work touch them). New code is new functions beside the old ones; `render` and `formatView` gain sections, nothing is rewritten.

## Changelog notes

- The pane and `turbo-run view` / `status --watch` show `Now: …` under the phase line, the phase's steps, what comes next and when you are needed; commits as a count by kind instead of raw subjects.
- In a terminal under 144 columns the pane opens with your next prompt, and until then the band says how to open it.
- `status --watch` is coloured by state on a terminal (`NO_COLOR` turns it off).
- `/turbo-autonomous` start says where to watch the run.
