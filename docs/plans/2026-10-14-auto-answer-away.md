# gsd-turbo v0.4.0 — auto-answer after an hour, and sleep mode

**Goal.** Owner ruling (2026-10-14): a question the owner leaves unanswered is taken by turbo itself after an hour, through the recommended option, but only for safe questions; and a sleep mode: answer what can be answered ahead in one batch, leave, and get a morning summary on return.

## Decisions

- **D1 Clock.** A question carries `askedAt` (ISO). It is stamped when the question is asked: `askOwner` and a stop (`stopQuestion`, status `stopped`) stamp `now`; a rebuilt question keeps it (`refreshQuestions` carries it) unless its options changed (a new `rev`: the clock starts again). A question without one (written before v0.4.0, or by a path that does not stamp) is stamped by the supervisor's owner tick the first time it sees it open. The wait is `now - askedAt`.
- **D2 Limit.** `owner.auto_answer_minutes`, default `60`; `0` is off. Anything but a whole number ≥ 0 is a config error that the owner tick logs, and nothing is answered (fails closed).
- **D3 Eligibility** (`autoChoice(q, records)`, pure): only an open question with no earlier record in the answers file (no second auto answer, never over an answer the owner gave before, a stop that reopened an answer, or an undo); never `human-action`, never `gate: "blocking-human"` (the checkpoint extractor already parses it and the question keeps it; dynamic stops are blocking-human too); a lane question (`turbo-run ask`, `source: "lane"`) only with `autoOk: true` (`ask --auto-ok`; the lane-markup card sets it, being reversible through its ADR; the merge card does not); `decision` only with exactly one recommended option (not a defer); `human-verify` through its first non-defer option ("Accept if the checks pass" ahead, "Approved" at a stop) and always with the plan's verify condition, so the executor checks the automated evidence and returns the checkpoint when it fails; and never when the question, context or any option label or description matches the deny list (money / payment / оплат, account / аккаунт / login / вход, deploy / prod / production / прод / деплой, delete / wipe / удал, sign / подпис, password / парол, live / живая проверка).
- **D4 Answer.** The owner tick (`lib/owner-tick.mjs`) runs `autoTick` after the notifications: every eligible open question whose wait reached the limit is answered through `answerQuestion` (the single arbiter, new channel `auto`, with `rev` and a `reason`: «no answer for N min: the plan's recommended option»), skipping attended phases. The normal paths then carry it: a stop is delivered by the supervisor's wake, an ahead answer goes into the executor's prompt. Each auto answer sends `autoAnswered` (desktop and Telegram): «Принято автоматически, пока вас не было: <question> → <option>. Отменить: turbo-run answer N <id> --undo».
- **D5 Undo.** `turbo-run answer N <id> --undo` (owner channels only, refused in a lane). Only a standing `auto` answer can be undone. Not yet delivered: the record is marked `superseded` and `undone`, the question opens again with a new `rev` (so it is notified and shown again) and a fresh clock, and it is never auto-answered again (D3). Delivered (the lane already took it): nothing is reopened; an `owner-correction` message goes into the phase's inbox (data for the lane). An ahead answer that was reopened also gets the inbox message, since an executor may already hold it in its prompt. The lane rule (turbo-phase skill): an `owner-correction` for a checkpoint already behind is asked to the owner with `turbo-run ask` (keep or redo); one still ahead needs nothing.
- **D6 Sleep mode.** `run/away.json` `{ since, ackAt, snapshot }` (its own file, one writer: the owner's commands; `supervisor.json` stays the daemon's). `turbo-run away [--json]` refreshes the questions of every unfinished phase of the run's range that no lane runs (a running lane's plans live in its slot; its questions file is already current), then prints every open question (the `questions --open` shape). `turbo-run away --set` records `since` and a snapshot (plans done per phase). `turbo-run back [--json]` prints the morning summary since `since` (phases progressed, commits, auto answers with their undo commands, questions still waiting, failed or stopped lanes) and clears `since` (`ackAt` = now). Telegram buttons: not added (the Telegram channel only polls while questions are open); the commands are named instead.
- **D7 Surfaces.** `turbo-run view` gains `away` and `autoAnswered` (auto answers not undone, newer than `ackAt`, newest 5); `formatView` and the pane draw an away line and «Accepted automatically while you were away (N)» with each question → option and its undo command. `turbo-run status` prints the same lines. The skill: `/turbo-autonomous away` (gather, ask 4 at a time like **Answer the open questions**, `away --set`); any other `/turbo-autonomous` call first runs `turbo-run back` while away.
