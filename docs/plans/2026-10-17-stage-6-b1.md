# Stage 6 B1 — headless sessions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `lib/headless.mjs` runs one short role session of the build path as `claude -p … --output-format stream-json`, with the prompt on stdin, the lane write guard, a timeout and a stall watch that kill the whole process tree, returns the session's id, transcript, result text, usage and owner question, continues the same session with `--resume`, and caps the headless sessions of the whole machine; a live probe confirms every `-p` behaviour the module relies on before B2–B4 build on it.

**Architecture:** Pure builders (argv, env, settings file, tree kill) come first and are what the live probe `scripts/headless-probe.mjs` launches, so a PASS validates the module's exact command line; the probe's findings set the module's two probe-fed constants. A pure stream-json reducer (`foldEvent`) and the owner-question parser are unit-tested on fixtures; `runSession`/`resumeSession` spawn claude through stage-5's `resolveBin`, watch stdout and the transcript tree for activity, and kill by `taskkill /T /F` (Windows) or the process group (elsewhere). `acquireSessionSlot` keeps numbered slot files under `<turbo home>/sessions/`, scanned under a short `withFileLock` mutex.

**Tech Stack:** Node.js ≥ 20 ESM, node:test, git, Claude Code CLI

**Spec:** docs/specs/2026-10-17-stage-6-lean-design.md (§6.2, §6.5, §6.10 `build.max_sessions` / `build.stall_min` / `build.timeout_min`, §8 risk "`claude -p` behaves differently from `--bg`")

**Base:** branch `stage-5` (`..\gsd-turbo-stage5`); topic branch `stage-6-b1`. Existing code is referenced by function name, never by line number.

## Global Constraints

- Zero-dependency Node ESM; tests `node --test` on named files only; never a step that runs the full suite. CI: Ubuntu/Node 22 + Windows/Node 24.
- Command: `claude -p --output-format stream-json --verbose --model opus --effort <e> --permission-mode bypassPermissions --settings <file> [--agent <name>] [--append-system-prompt-file <file>]`, prompt via stdin (spec §6.2); `--resume <sessionId>` with the owner's answer on stdin continues the same session (§6.5).
- Effort values: `low`, `medium`, `high`, `xhigh`, `max`. Model `opus` (owner policy: Opus everywhere, spec §2).
- `build.max_sessions` default `6` (1–20), machine-wide; `build.stall_min` / `build.timeout_min` defaults `15` / `120` (§6.10). B1 reads no config: callers pass `max`, `stallMin`, `timeoutMin` (from L1's `buildSettings(cfg)`).
- Stop: after `timeoutMin`, and after `stallMin` without new transcript lines or stream events, the process tree is killed (Windows-safe) and the result says `timedOut` / `stalled` (§6.2).
- OWNER QUESTION block: heading `## OWNER QUESTION`, then `Question: <one line>`, `Context: <up to 600 characters, may span lines until Options:>`, `Options:` and numbered `<label> — <description>` lines; at most 4 options, `(recommended)` on at most one; no options = free-text question; tolerant of `-`/`–`/`—` and CRLF.
- Write guard: the same settings as lanes (`lanes.write_guard`, `laneSettings`), the session's cwd (the slice worktree) as an allowed root.
- Windows: no shell, `windowsHide: true`, argv arrays; `taskkill /T /F /PID` on win32, `process.kill(-pid, 'SIGKILL')` on a `detached` child elsewhere.
- Tests never run a real `claude`, never touch the developer's Claude home (`CLAUDE_CONFIG_DIR` points into a tmp dir). Only the probe runs real claude, and only when the controller runs it.
- `scripts/headless-probe.mjs` is not shipped: `install.mjs` copies only `bin/` and `lib/` (and `package.json` `files` has no `scripts`); nothing to change there.
- Commits: conventional, English, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push, merge, tag or install.

## Review Focus

1. **A killed session leaves its children running** (a builder's `npm test`, a hook, a node server): on Windows `taskkill /T` from the claude pid, elsewhere the process group. Pinned in Task 5 (`stall kill ends the grandchild too`) and Task 1 (`killTree ends a process and its child`).
2. **A grandchild that keeps stdout open hangs `runSession`** (Windows: `close` never fires while any inheritor holds the pipe). Pinned in Task 4 (`a grandchild holding stdout does not hold the result`).
3. **Usage counted twice**: stream-json repeats one assistant message per content block with the same `message.id`. Pinned in Task 2 (`without a result, usage is the last usage of each distinct message id`).
4. **The calling session leaks into the child** (`CLAUDECODE`, `CLAUDE_CODE_SESSION_ID`, the messaging socket of the owner's session) — a nested-session refusal or messages into the owner's session; and a Cyrillic owner answer garbled on stdin. Pinned in Task 1 (`headlessEnv …`) and Task 4 (`… scrubs the calling session …`, Cyrillic prompt in the first test).
5. **Two processes take the same slot**, or a crashed holder blocks a slot forever (dead pid, Windows pid reuse). Pinned in Task 6 (`two processes with max 1 never overlap`, `a dead holder's slot is taken at once`, `a slot not refreshed for staleMs is taken`).

## Planner decisions

- `--disallowedTools AskUserQuestion` is added to every headless session, as for lanes; the OWNER QUESTION block replaces it.
- Settings go in a file (`settingsFile` of the brief) built by `sessionSettings` from stage-5's `laneSettings`, made `export` in `lib/claude.mjs` (a one-word hunk away from L1's `buildBgArgs` change); the file lies next to, not inside, the session's temp directory so the session cannot rewrite its own guard.
- Env: `headlessEnv` = `sessionFreeEnv` minus `DROP_ENV` (the calling Claude Code session's markers, its messaging socket and token, and `CLAUDE_EFFORT`); `CLAUDE_CONFIG_DIR` and user preferences stay. `opts.env` is the base env, always scrubbed.
- Usage: the result event's `usage` (unless the probe shows it is last-turn only), else the last usage of each distinct `message.id`.
- Activity for the stall watch: any stdout line, or the newest mtime of the transcript tree (`sessionTreeMtimeMs`, subagents included).
