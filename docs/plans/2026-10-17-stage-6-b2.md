# Stage 6 B2 — ready queue, worktrees, merge, state Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The deterministic mechanics of the build step (§6.3 step 5): the slice graph and ready queue, the build state file `run/build-p<N>.json`, one git worktree per slice, the merge of a finished slice into the phase branch under a lock, targeted tests of exactly that merge (`turbo-run test-changed --merge <sha>`), owner cards that hold only the slice that asked (`turbo-run ask … --keep-running`), and crash recovery with salvage branches (§6.6). No model, no sessions: B4 drives these functions, B1 runs the sessions, B3 writes the prompts.
**Architecture:** One new module `lib/build-queue.mjs` (pure state + graph functions, sync git operations through an injectable runner, one async test runner). It reuses `lib/exec-graph.mjs` as adopted on `stage-6` (only `remaining` gets exported), `lib/fsx.mjs` (`writeJsonAtomic`, `readJsonState`), `lib/questions.mjs` (`withFileLock`, `readQuestions`), `lib/merge-lock.mjs` (`pidAlive`), `lib/slots.mjs` (`slotsDir`, `copyPlan`, plus two exports), `lib/worktrees.mjs` (`outsideLinks`). Small hunks elsewhere: `lib/test-changed.mjs` (`merge` option), `bin/turbo-run.mjs` (`--merge`), `lib/questions.mjs` + `lib/cli-phase.mjs` (`keepRunning`), `lib/strays.mjs` (turbo's own names).
**Tech Stack:** Node.js ≥ 20 ESM, node:test, git, Claude Code CLI
**Spec:** docs/specs/2026-10-17-stage-6-lean-design.md (§6.3 step 5 mechanics, §6.4, §6.6, §6.10 `build.max_builders`; §9 row B2)

## Global Constraints

- Base: branch `stage-6` (worktree `..\gsd-turbo-s6`: stage-5 + stage-6-base + the spec); topic branch `stage-6-b2`.
- Zero-dependency Node ESM; tests `node --test` with `test/helpers/*`; CI Ubuntu/Node 22 + Windows/Node 24.
- git only through `execFileSync`/`spawn` with an argument array, `windowsHide: true`, a timeout, never a shell; paths given to git with `/`.
- State file `run/build-p<N>.json`, `"v": 1`, written with `writeJsonAtomic` (data flushed with fsync before the rename, rename retried on Windows).
- Slice states exactly: `waiting`, `dispatched`, `running`, `merged`, `owner`, `failed`, `blocked`, `done-before`.
- Edges: `depends_on` + shared written files (`files_modified` ∪ `files_deleted`) + `key_links` reads, only forward in plan order (exec-graph `planEdges`, all `EDGE_KINDS`).
- Slices whose SUMMARY is in HEAD → `done-before`; `gap_closure: true` slices are a separate round.
- `build.max_builders` default 4 (1–12): B2 never reads config for it; the caller passes `maxBuilders` (L1's `buildSettings(cfg).maxBuilders`).
- Worktree: `git worktree add` from the phase branch HEAD; branch `turbo-build/<id>`; removed after its merge.
- Merge: verify SUMMARY + ≥ 1 commit + no `## Self-Check: FAILED`; `git merge --no-ff` under lock `locks/build-p<N>`; retry on `index.lock`/`config.lock` after 2/4/8 s; conflict → `git merge --abort`, `{ blocked: true, reason }`; success → the merge sha.
- `turbo-run test-changed --merge <sha>`: targets = files of `<sha>^1..<sha>`; not counted in `test.max_targeted`; full only by its own rules.
- Red HEAD: no new dispatch while `state.red`; cleared only by a green retest.
- Salvage branch `turbo-salvage/<id>-<UTC>`; never delete a branch whose commits are on no other ref.
- An owner card asked with `keepRunning` never turns the lane `needs-owner`.
- No claude anywhere in B2's tests; real git in tmp repos; never a step that runs the full suite.
- Commits: conventional, English, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A worktree removal never deletes through a link** (memory: a worktree cleanup through a junction once deleted the main checkout's `node_modules`): links are unlinked as links first, and nothing is removed while an outside link remains. Pinned in Task 4 (`removeSliceWorktree keeps the lane checkout's node_modules`).
2. **No dispatch that the rules forbid:** none while `red`, `hold`, or a merged slice has `tests: null`; never a slice whose predecessor is not `merged`/`done-before`; an `owner` slice holds only its dependents and takes no builder seat; a held card writes no lane status and no later `ask` supersedes it. Pinned in Task 3 and Task 2.
3. **Nothing lost or done twice after a crash:** a branch already merged is not merged again (the existing merge sha is found by its subject), a slice merged but not yet saved is not requeued, partial work (commits and uncommitted files) lands on a salvage branch before its worktree goes. Pinned in Task 5 (`already merged`) and Task 6.
4. **A failed merge leaves the phase checkout as it was:** conflict, artifact or lock failure → no `MERGE_HEAD`, HEAD unchanged, clean status, slice branch and worktree intact. Pinned in Task 5.
5. **`--merge` never corrupts the full-run bookkeeping:** the marker is untouched by a targeted merge run, the count never grows, a later plain run still owes the full run it owed, the phase-end rule does not apply, a non-merge sha is refused with exit 2. Pinned in Task 1.

## Planner decisions

- Slice id = the plan id (`33-07`, exec-graph `planIdOf`); it already carries the phase, so names use it alone: `<lanes dir>/b/33-07`, `turbo-build/33-07`, `turbo-salvage/33-07-<yyyymmddThhmmssZ>`.
- Worktrees live in the slots folder (`<parent>/<repo>.turbo/b/<id>`, or `lanes.dir/b`), not inside the lane checkout: a nested worktree would be picked up by the checkout's test runner and linters (ESLint 9 lints dot-folders) in the per-merge and final full runs, and a builder whose guard root is its own worktree cannot write into another slice. It is shorter than a path inside a slot (MAX_PATH).
- A slice worktree gets the lane's `node_modules` of each `test.full` directory as a link (junction on Windows), the `lanes.copy` files, and the lane's test marker when its full run is an ancestor of the base, so builder tests run targeted. Links are hidden in a turbo block of `info/exclude`. Other ecosystems (venvs) are not linked.
- `mergeSlice` is synchronous under `withFileLock` `locks/build-p<N>` (60 s wait, 30 min stale, owner by pid); a B4 process lock must use another file name.
- Lock errors: `LOCK_ERROR` (any `Unable to create '….lock'`, `index.lock`, `config.lock`), retries after 2/4/8 s, then `blocked` kind `lock`; blocked kinds `artifacts`, `dirty`, `checkout`, `conflict`, `lock`, `git` let B4 apply its policy (a conflict is rebuilt once from the new HEAD).
- Merge commit subject `chore(phase-<N>): merge slice <id>`; it is how a merge is found again after a crash.
- `--merge`: the phase-end rule does not apply (the build path's one full run is step 10), the count never grows, the marker changes only when an entry ran full, no marker → full, a non-merge or unreachable sha → exit 2.
- The retest after a red merge is a plain `test-changed` (counted); `runMergeTests` logs to `<runDir>/build-p<N>/tests-<sha7>.log` (`tests-retest-<ms>.log`), 30 min limit through `tree-timeout.mjs`.
- `nextReady` also stops while a `merged` slice has `tests: null` (a merge from reconcile is tested before anything new forks from it) and while `state.hold` is set (pause, attend); `owner` slices take no builder seat; priority = longest chain of slices (weight 1) through exec-graph `remaining`, then plan order.
- The state file goes where the caller says (`runDir` argument); recommended for B4: the control root's `runDir(root)`, which a slot's clean never reaches and the pane can read.
- A damaged state file throws `BuildStateDamaged` (never read as a fresh start); reconcile handles orphan `turbo-build/*` branches anyway, so a fresh state after one loses nothing.
- Salvage commits uncommitted worktree files as `wip(<id>): uncommitted work salvaged by turbo` and deletes `turbo-build/<id>` only after the salvage ref resolves to the same commit.
- Reconcile never kills a process; a slice whose recorded `pid` is alive is reported `alive`. B4 records the pid when B1 exposes it (null reads as gone).
- `keepRunning` cards: `held: true`, no lane status, never superseded by a later `ask`, kept by `dropLaneQuestions` (which gains `{ ids }` for the build to close a card itself).
- B2 imports nothing of L1, B1 or B3 (`maxBuilders` is passed in), so it builds and tests on `stage-6` alone.
- Gap rounds: `planGraph({ gaps: true })` and a new state with `round` k ≥ 1 (B4 counts `gap_rounds`).
- Exec-graph changes are limited to `export function remaining`; everything else is taken as reviewed on `stage-6`.
