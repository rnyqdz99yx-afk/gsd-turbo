# Stage 6 B3 — role prompts, compact GSD plans, slice lint Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The three model roles of the build path (slicer, builder, fixer) as short prompt files filled by code, a compact PLAN/SUMMARY format that GSD 1.17's own tools read as planned / executed / complete, and a deterministic check of a phase's slices (fields, size, tasks, files, REQ-ID and decision coverage, depends_on, edges).
**Architecture:** `roles/*.md` hold the prompt copy with `{{name}}` placeholders (one shared fragment `roles/owner-question.md`); `lib/roles.mjs` `rolePrompt(role, ctx)` fills them from ctx, the phase directory, the slice's plan frontmatter and L1's phase signals and returns the whole prompt (B4 sends it on stdin). `lib/slice-lint.mjs` `lintSlices(root, phase)` reads the phase's `*-PLAN.md`, runs GSD's deterministic verbs (`verify plan-structure`, `check decision-coverage-plan`) through gsd-tools, adds the turbo rules in code and builds the edges with `lib/exec-graph.mjs`. A real-GSD test (skipped without GSD) pins the format the prompts show against the installed gsd-tools.
**Tech Stack:** Node.js ≥ 20 ESM, node:test, git, Claude Code CLI
**Spec:** docs/specs/2026-10-17-stage-6-lean-design.md (§6.3 steps 4–6 prompt content and checks, §6.5, §6.9; D4, D5)

## Global Constraints

- Code base: branch `stage-6` (worktree `..\gsd-turbo-s6`); `lib/exec-graph.mjs` there (with d2a0dbf) is consumed as is.
- B3 owns `roles/*.md`, `lib/roles.mjs`, `lib/slice-lint.mjs`; it also touches `install.mjs` (one word), `package.json` `files`, `test/install-stage2.test.mjs`, `docs/reference.md` (one new section). Nothing else.
- Roles: `slicer`, `builder`, `fixer`. Installed to `~/.claude/turbo/roles/`.
- Rendered budgets (bytes, UTF-8): builder ≤ 6144, slicer ≤ 8192, fixer ≤ 6144 — with the test fixtures below (600-character pre-answers, long phase slug).
- Slice plan: `NN-MM-PLAN.md`, ≤ 8 KB (8192 bytes), ≤ 5 tasks, own files, each unverified external assumption a spike slice first, cites the D-NN decisions it implements.
- Plan frontmatter: GSD's required `phase, plan, type, wave, depends_on, files_modified, autonomous, must_haves` plus `files_deleted`, `requirements`, `must_haves.key_links`; optional `spike: true`, `gap_closure: true`.
- OWNER QUESTION block, exactly (B1 parses it):
  `## OWNER QUESTION` / `Question: <one line>` / `Context: <up to 600 characters>` / `Options:` / `1. <label> — <description> (recommended)` / `2. <label> — <description>`.
- SUMMARY: GSD summary schema fields `phase, plan, subsystem, tags, duration, completed` + `requirements-completed`, `status: complete`; ends `## Self-Check: PASSED` or `## Self-Check: FAILED`; a blocked slice writes `status: blocked` (GSD does not count it).
- Lint: deterministic, no model; `{ ok, problems: [{ plan, kind, detail }], edges }`; `plan` is the plan id or `null` for the phase.
- gsd-tools verdict verbs run WITHOUT `--raw` (with it `verify plan-structure` prints `valid`); exit 0 and 1 are verdicts with JSON on stdout, any other exit = could not look.
- L1 interfaces consumed (not implemented): `readPhaseInfo(root, phase)`, `needsResearch(info)`, `needsSecurity(info)` from `lib/phase-signals.mjs`.
- Zero dependencies; Windows-safe paths (prompts and gsd-tools arguments use paths relative to the root with `/`).
- Tests: targeted files only; never the full suite. Commits: conventional, English, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **gsd-tools verdict parsing** — `--raw` turns `verify plan-structure` into the word `valid`; an invalid plan exits 1 (a verdict, not a failure); a missing file exits 69. Pinned in Task 5 (`gsdVerdict` against a stub core; the recorded argument lists have no `--raw`).
2. **Installed layout** — `lib/roles.mjs` must find `../roles` next to itself in `~/.claude/turbo`, not in the checkout. Pinned in Task 4 (imports the installed `roles.mjs` and renders).
3. **Prompt format drifting from GSD** — the PLAN and SUMMARY the prompts show must stay valid for the installed GSD (required fields, decision-citation surfaces, a blocked SUMMARY not counted, the planned → executed → complete ladder). Pinned in Task 7 (the format is cut out of the rendered prompts, not retyped).
4. **Budgets** — long phase slugs and pre-answers push the builder over 6 KB. Pinned in Tasks 1–3 (exact byte limits on worst-case fixtures).
5. **Windows paths** — absolute ctx paths with `\` leaking into prompts or gsd-tools arguments. Pinned in Task 1 (no `\` in a prompt rendered from `path.join` paths) and Task 5 (recorded gsd arguments are `/`-relative).

## Planner decisions

- The role copy lives in `roles/*.md` with `{{name}}` placeholders; the OWNER QUESTION paragraph is one shared fragment, `roles/owner-question.md`.
- `rolePrompt` returns the whole prompt for stdin (not an `--append-system-prompt-file`); paths are rendered relative to `ctx.root` with `/`.
- Optional ctx additions: `info`, `signals` (slicer; default L1's functions), `lang` (default `loadConfig(root).lang`), `findingIds` (fixer). `lintSlices` adds options `{ gsd, core, info }`.
- The slicer gets goal, success criteria and requirement ids + texts inlined from `readPhaseInfo` (no ROADMAP read); the lint takes the REQ-IDs from the same source, so the prompt and the check never disagree.
- The spike-first rule is always in the slicer prompt; L1's `needsResearch`/`needsSecurity` add a `## Signals` paragraph naming why; open `needs_research` items are listed only when there is no RESEARCH.md.
- Gap round = the slicer with `findingsPath` (VERIFICATION.md): new slices `gap_closure: true`, numbered after the existing ones (matches B2's gap round).
- A spike slice is marked `spike: true` (GSD ignores unknown frontmatter keys; verified on 1.17).
- The SUMMARY skeleton is inlined in `builder.md`: GSD's `summary.compact.md` is 9.6 KB, over the builder budget; the skeleton keeps every field GSD's summary schema requires plus `requirements-completed` and `status`.
- A builder that needs a file outside its list stops with a `status: blocked` SUMMARY and `## Self-Check: FAILED` (GSD does not count it; B2 refuses to merge it), not with an owner question — code decides what happens next.
- The slicer does not commit; B4 commits the plans after the lint passes. The builder commits its SUMMARY with plain git so the merge carries it (the build path needs committed planning docs; `commit_docs: false` projects are B4's eligibility question).
- Fixer scope: REVIEW → Critical (`CR-`/`BL-`) and Warning (`WR-`) — the spec's critical/high/medium; SECURITY → open critical/high `mitigate` threats; any other file → failing-test output; `findingIds` narrows it. Commits use GSD code-fixer's `fix(<padded phase>): <id> <what>`.
- REQ-ID coverage is GSD plan-phase §13's rule (every phase REQ-ID in some plan's `requirements` frontmatter) computed in code: GSD has no gsd-tools verb for it (`gap-analysis` is advisory and counts any mention in the text).
- Structure and decisions come from GSD itself (`verify plan-structure` per plan, `check decision-coverage-plan`); a project that turned `workflow.context_coverage_gate` off gets GSD's skip.
- The lint does not flag declared waves (GSD recomputes them from `depends_on`) or shared files (they become edges); it flags `depends_on` tokens naming no slice and cycles.
- `lintSlices` is synchronous: N + 1 gsd-tools calls, about 2 s each on Windows.
- Without L1 on the base, a placeholder `lib/phase-signals.mjs` in its own commit; the integrator takes L1's file.
- Docs: one new section after `## What-if: plans as a graph`.
