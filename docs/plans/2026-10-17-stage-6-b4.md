# Stage 6 B4 — the build path driver Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `turbo-run build <N> [--resume] [--json]` runs one GSD phase by code: begin → discuss → research (by condition) → slice (+ lint, one revision, else the owner) → build (ready queue, parallel slice sessions in worktrees, merge + merge tests, one fixer on red, one rebuild on conflict, owner questions holding only dependents) → review (one fixer pass, diff-only re-review, a second round only for a new critical) → verify (one pass, gap rounds) → security (by condition) → uat (turbo-uat) → tests (full run, push and CI) → close (`phase.complete`, done/ready record). Every step is idempotent and recorded on disk; a killed run continues with `--resume`. The supervisor launches it as a detached child instead of a `/turbo-phase` session for eligible phases, restarts it when it dies, and the views show its step, slices and cards.
**Architecture:** `lib/build.mjs` is the step machine. It keeps its step record as sibling fields of B2's `run/build-p<N>.json`, runs model work only through B1 sessions (B3's role prompts, GSD agents via `--agent`, GSD workflows), and reuses stage-5 code for cards, answers, tests, push, UAT and integrate. `lib/build-lane.mjs` is the supervisor's side: §6.8 eligibility, one runner per phase (a lock with a heartbeat), the detached launch and the tree stop. In the supervisor a build lane is an ordinary lane record with `path: 'build'` and a `pid`; its liveness becomes a synthetic agent, so the existing status, restart, done and merge paths run unchanged, and a few guards keep the claude-only paths (stall and answer wakes, `claude rm`, `claude stop`) off it. The view gains `lane.build`, printed with the same words by `lib/view.mjs`, the mod and `turbo-run status`.
**Tech Stack:** Node.js ≥ 20 ESM, node:test, git, Claude Code CLI

## Global Constraints

- Steps exactly: `begin`, `discuss`, `research`, `slice`, `build`, `review`, `verify`, `security`, `uat`, `tests`, `close`. Slice states exactly B2's eight: `waiting`, `dispatched`, `running`, `merged`, `owner`, `failed`, `blocked`, `done-before`.
- §6.10: `build.enabled` default `false`; `build.max_builders` 4 (1–12); `build.max_sessions` 6 (1–20); `build.effort` `{ slicer: high, builder: high, fixer: high, researcher: medium, reviewer: high, verifier: medium }`; `build.stall_min` / `build.timeout_min` 15 / 120; `build.adopt_plans` false (L1); `gap_rounds` (existing, default 1).
- §6.3: research effort medium, RESEARCH.md ≤ 25 KB, no second code scan; slice = one slicer session (effort high), deterministic check, one revision of the same session (`--resume`), then the owner; build: worktree from the phase branch HEAD, merge `--no-ff` under the lock, `test-changed --merge <sha>`, red → no new dispatch, one fixer, retest, else the owner; conflict → one rebuild from the new HEAD, then the owner; review: `gsd-code-reviewer` (standard) on the phase diff, findings critical/warning → one fixer → review of the fix diff only → a second round only for a new critical; critical/high never closed by a document; verify: `gsd-verifier` one pass, `gaps_found` → gap slices (`gap_closure: true`), ≤ `gap_rounds`; security by condition (`gsd-security-auditor`); UAT turbo-uat; tests: full run (`test.full`) + push/CI through Stage 3 (`push.mode`); close: `gsd-tools phase.complete`, the turbo done record, slots integration unchanged.
- §6.4: ≤ `build.max_builders` builders per phase, longest remaining path first; an owner question holds only its dependents (held card, `keepRunning`); red HEAD → no new dispatch; ≤ `build.max_sessions` headless sessions per machine.
- §6.5: a session that needs the owner ends with `## OWNER QUESTION`; code asks the card and continues **the same** session with `--resume` and the answer; pre-answers go into the role prompt.
- §6.6: at start the state is reconciled with git and the disk; nothing merged twice, partial work on `turbo-salvage/<id>-<UTC>`; the supervisor restarts `build N` when its process dies; before a pause nothing new is dispatched and running sessions finish and merge.
- §6.7: attend N of a build phase pauses dispatch, waits for running sessions, hands the phase to the owner; `attend N --done` → the build continues from disk. Pane, band and `turbo-run status` show the step, slices (id, state, time, last action) and cards.
- §6.8: refusal with the reason when `build.enabled` is false, the phase is attended, it touches a submodule, it has GSD-planner PLAN files without SUMMARY (unless `build.adopt_plans: true`), or `depends_on` has a cycle; a phase started on build finishes on build.
- CLI: `turbo-run build <N> [--resume] [--json]`; exit 0 closed, 1 failed, 2 usage or refused, 3 paused or already running.
- Windows-safe: argv arrays, no shell, `windowsHide: true`, detached children with `unref()`, process trees ended with B1's `killTree`.
- Tests: `node --test` on named files only; never the full suite; never a real `claude` (the demo script is a controller step); real GSD only in tests skipped without GSD 1.16/1.17.
- Commits: conventional, English, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Work done twice after a crash or by two processes.** A second `build N` while one runs, a re-sliced phase, a merged slice rebuilt, round 1 of the review run again, a card asked again: Task 2 (`claimRunner: one holder per phase…`), Task 8 (four crash tests counting role sessions and merge commits, and the killed-process test).
2. **The supervisor reads a build lane as a dead claude session.** A relaunch every tick, a stall or answer wake that runs `claude --resume null`, `claude rm null`, `claude stop` on the build, two builds of one phase: Task 10 (`a live build lane is never stall-woken…`, `…adopted, never launched twice`, slots tests).
3. **An owner question blocks too much or its answer goes astray.** The waiting slice must hold only its dependents, its card must not touch the lane status, the answer must reach the same session once: Task 3 (`an owner question becomes a held card…`), Task 5 (`slices run in parallel and an owner question holds only its dependents`).
4. **A red merge or an open critical passes silently.** Nothing new dispatched while red; one fixer; still red → card; an old critical after the fix round → card, never a second fixer round: Task 5 (`a red merge stops new slices…`, `red after the fix stops for the owner`), Task 6 (`review: an old critical still open goes to the owner…`).
5. **A pause that kills or keeps dispatching.** attend and the owner's first `stop` must let running slices finish and merge and start nothing new; an old owner-stop mark must not pause a new run; the second `stop` ends the build: Task 5 (`attend and stop pause the queue…`), Task 10 (`stop asks a running build to pause first…`, `attend of a build lane waits…`).

## Planner decisions

- The step record is B4's sibling fields of `run/build-p<N>.json` (`step`, `steps`, `base`, `roundBase`, `gapRounds`, `info`), written through B2's `saveBuildState`; before slicing the file is `newBuildState` over an empty graph; a round's graph replaces only B2's fields.
- A build lane in supervisor.json is the lane record with `path: 'build'`, `pid`, `sessionId: null`. Liveness: the runner lock `locks/build-run-p<N>.json` (pid, 60 s heartbeat, stale after 5 min), or a pid launched less than 5 min ago. The supervisor turns it into a synthetic `working` agent, so `inferStatus`, `relaunchDecision`, the done path and the slots merge path run unchanged.
- Build lanes are never stall-woken (the build stops its own sessions, B1) and never answer- or inbox-woken: an answer, `reintegrate` or `ci-red` relaunches `build N --resume`, which reads its cards and inbox itself.
- Every card the build path asks is held (`keepRunning: true`) and never `autoOk`; the build process waits for it, polling every 5 s. Lane statuses the build writes: `done` (checkout close), `ready` (slot close), `failed` (a failure, a refusal under `TURBO_BUILD_LANE`, the owner's Stop here); the supervisor writes `running`.
- "Stop to the owner" is one held halt card per kind with Try again / Go on (only `slices`, `review`, `verify`, `security`) / Stop here; the owner's own words count as Stop here; a stopped step is tried afresh by the next `--resume` (`resume N`).
- A card a session cannot ask (plain-words check, option count) goes back to the same session once with the reason; twice → the step fails.
- attend kills nothing: the build pauses (no dispatch, running sessions finish and merge) and exits 3; `attend` waits up to `build.timeout_min + 10` min; its gates line keeps GSD's gates on. `turbo-run stop`: the first lets the build pause the same way through the owner-stop mark (only a mark newer than the run counts), the second (the state shows `hold: stop`) ends the process tree.
- On `--resume`, sessions recorded as alive are ended first (their output cannot be read again); B2's reconcile then merges finished slices and salvages partial ones.
- A run without `--resume` refuses an existing state (exit 2); the supervisor adds `--resume` whenever the state file exists.
