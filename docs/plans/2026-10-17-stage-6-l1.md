# Stage 6 L1 — lean keys and switches Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lean mode on by default in every turbo project: GSD's lean keys written through `gsd-tools config-set` with their previous values kept for `lean off`, GSD's own effort mechanism lowering the planner, the assumptions analyzer and the researcher machine-wide, `--effort` on every lane session, lean applied only at a phase boundary, doctor without false warnings, the §5.2 predicates for L2 and B3, a STATE.md budget, prep of the next phase only, lane markup only when it pays, and every new key of §6.10 validated in one place.

**Architecture:** `lib/config.mjs` holds the §6.10 keys and four getters. `lib/lean.mjs` is the lean module: the GSD key table, `leanApply`/`leanOff` (config-set + `.planning/turbo/lean-prev.json` + one commit), the effort step (`~/.gsd/defaults.json` + `gsd-tools effort sync`, reachable only when a caller injects it), `leanStatus`, `leanBoundary` (D10) and the `turbo-run lean` command. The supervisor calls an optional `deps.leanBoundary(phase)` before a checkout-mode lane launch and before a slot is prepared for a phase; `bin/turbo-run.mjs` wires it, `init` and `adopt` inject `leanApply`. `lib/phase-signals.mjs` reads a phase's GSD files and answers `needsResearch`/`needsSecurity` with a `why`. `lib/state-sync.mjs` trims STATE.md history to `lean.state_budget_kb`; `lib/prep.mjs` takes a `prep.lookahead` window and gates markup on three independent phases.

## Planner decisions

- P1 `lanes.effort` goes on every session `startLane` launches (phase lanes, prep and annotate jobs), never on `claude --bg --resume` (any flag there starts a copy); persistence across a wake is Task 8's live check, with `effortLevel` in the lane `--settings` as the fallback.
- P2 Phase boundary = turbo's phase record has no `gates-off` and the phase directory has no plan SUMMARY (covers safe-mode lanes without turbo records); hooks before a checkout-mode launch or relaunch and before a slot is prepared for a phase; a slot lane's relaunch keeps its slot's settings; failures never block a launch.
- P3 Lean writes all keys at project level, `graphify.auto_update` included (GSD has no lane-only config).
- P4 `lean apply` refuses while any phase has its gates off (`gates restore` would put back the pre-lean values of three lean keys).
- P5 `lean-prev.json` keeps each key's value from before turbo first changed it; `off` restores, deletes the file and sets `lean.enabled` false (or the next boundary re-applies); `apply` sets it true when it was false.
- P6 Effort runs GSD's `<Claude config dir>/gsd-core` with `--config-dir <Claude config dir>` from the project root (so a project's own `effort` block still wins, GSD's rule); it acts only when that dir has `agents/gsd-planner.md` and the tool; an unparsable `defaults.json` is never rewritten; lib code gets no effort step unless a caller injects one (only `bin` and `cli-adopt` do).
- P7 `init` and `/turbo-adopt` apply lean without a commit of their own (init commits nothing today; adopt's single commit carries it); a lean failure in init is a warning.
- P8 Ranges not in the spec: `lean.state_budget_kb` 4–1024, `build.stall_min` 1–120, `build.timeout_min` 5–720 with stall < timeout; `build.adopt_plans` (§6.8) added to `buildSettings` as `adoptPlans` so L1 stays the only writer of `config.mjs`.
- P9 STATE budget: history = the named template sections plus headings that say history/archive (EN/RU); protected names win; largest first until within budget; table headers stay; moved text goes to `.planning/STATE-ARCHIVE.md` (GSD's own prune file); applied by the lane's `turbo-run state-sync` only, not by the supervisor's merge path.
- P10 The prep window is the next `prep.lookahead` unfinished phases after the running phase lanes, prepared ones included, so prep never runs further ahead during a run and a plan-only run prepares one phase.
- P11 Markup counts the whole milestone's unfinished phases (transitive `Depends on`); an answered dependency card still runs; `/turbo-adopt`'s one-time markup is unchanged.
- P12 `needs_research` items are the bullets of the DISCUSSION-LOG's `## External Research` (where GSD's assumptions mode records the analyzer's flagged topics); keyword sets are EN + RU; planned files = `files_modified` + `files_deleted`.
- P13 `lean` is an owner command (`OWNER_COMMANDS`): typed in a slot it acts on the control root; `apply`/`off` are refused in a lane; manual `apply`/`off` take the merge lock.
