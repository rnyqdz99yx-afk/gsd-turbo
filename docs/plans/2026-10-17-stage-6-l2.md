# Stage 6 L2 — lean phase steps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In lean mode `/turbo-phase` researches and audits security only when the phase calls for it, gives GSD's researcher, planner, checker and executor a smaller job, closes code-review findings in one fixer pass plus a review of its diff, re-verifies after fixes without GSD's serial chain, runs one full test suite per phase, and makes one records commit per step; with lean off every GSD call, prompt and command output stays byte for byte as stage-5. **Architecture:** lean is decided per phase (`phaseLean`, pinned when `gates-off` is done) and announced by `turbo-run phase-step N` as a first line `lean: on`; the deterministic decisions live in code behind the L2-owned `turbo-run jobs N <kind>` command (new kinds `research`, `regate`, `review`) and in `test-changed`; the prompt inserts are constants in `lib/lane-prompt.mjs` that the skill copies verbatim (the release-rule mechanism); `skills/turbo-phase/SKILL.md` gets one `## Lean mode` section and one-line `**Lean:**` sub-bullets, so stripping them gives stage-5's text byte for byte. **Tech Stack:** Node.js ≥ 20 ESM, node:test, git, Claude Code CLI
**Spec:** docs/specs/2026-10-17-stage-6-lean-design.md (§5.2, §5.3, §5.4 planner budget / executor references / service commits, D10 for the per-phase switch, §9 row L2)

**Base:** branch `stage-5` (`..\gsd-turbo-stage5`, ae8af80). Existing code is named by function and anchor text, never by line number.

## Global Constraints

- Lean on for phase N ⇔ `phaseLean(root, N)`: the pin in `run/lean-p<N>.json` if present; else `false` when its execution began — step `gates-off` done, or a plan SUMMARY in its directory (L1's `executeBegun` rule; D10, the owner's phase 33); else `leanSettings(loadConfig(root)).enabled` (L1; default `true`).
- Lean off: GSD calls, subagent prompts, `jobs`/`phase-step`/`test-changed` outputs and the lane system prompt are stage-5 byte for byte (Task 1 golden).
- Research only when `needsResearch(readPhaseInfo(root, N)).yes` or RESEARCH.md exists; otherwise `gsd-plan-phase N --chunked --skip-research` (spec §5.2).
- Security audit in turbo's fan-out only when `needsSecurity(readPhaseInfo(root, N)).yes` (GSD's `workflow.security_enforcement` is `false` under lean, L1).
- Plan checker: `research_resolution` and `scope_sanity` are severity `info`, never a revision (spec §5.2).
- Review → fixes: one fixer pass, then a review of the fix diff only; a second pass only for new critical findings; at most 2 fixer passes (`phase-step N --attempt fix`). A critical finding is never closed by documentation alone, only by a code change or the owner's decision (spec §5.3).
- final-gate: re-run only the gates whose input files changed, plus the verifier alone; never `gsd-execute-phase N --no-transition` with the gates back on for re-verification (spec §5.3).
- `test-changed` under lean: no full run before `final-gate` is done; a run it cannot target is a skip with a note; the one full run is final-gate's `TURBO_FULL=1`, plus CI (spec §5.3).
- Planner: PLAN ≤ 25 KB, no restating RESEARCH, no code block over 10 lines, every checker-required field kept (spec §5.4).
- Executor references: `checkpoints.md` only for a plan with a checkpoint task; never `executor-examples.md`; `tdd.md` when GSD passes it; `worktree-path-safety.md` always (spec §5.4).
- One docs commit per turbo step for turbo's records (owner answers, resume position, planning bases) (spec §5.4).
- Inserts are plain argv values: no `"`, no `%`, no `<` or `>`, never a leading `-` (as `RELEASE_RULE`).
- Interfaces consumed exactly as the brief: `leanSettings(cfg) → { enabled, stateBudgetKb }`; `readPhaseInfo(root, phase)`; `needsResearch(info)`, `needsSecurity(info) → { yes, why }`.
- L1 owns `lib/config.mjs` and `lib/phase-signals.mjs`: L2 adds only the Task 1 stubs (one commit, dropped at integration).
- Zero dependencies; Windows-safe paths (git prints `/`; `path.join` for the disk); commits conventional, English, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tests: targeted files only (`node --test test/a.test.mjs …`); never the full suite. A stage-5 test that fails only because lean is now on by default gets `"lean": { "enabled": false }` in its turbo config (`.planning/turbo/config.json`); its assertions never change.

### Task 6: the lean review loop

**Files:** Modify `lib/review-loop.mjs`, `lib/cli-phase.mjs` (`jobs`); Modify `test/review-loop.test.mjs`.
**Interfaces:** Produces `fixReportEntries(text) → [{ code, title, section: 'fixed'|'skipped', commits: string[], files: string[] }]` (REVIEW-FIX.md `## Fixed Issues` / `## Skipped Issues`, `### <code>: <title>`, `**Commit:**`, `**Files modified:**`); `reviewDiffText({ since, open })`; `leanReviewNext({ review, fixReport = null, previousReview = null, since, fixedAfterReview, diffReview, changedCode = [], commitFiles = () => null, exists = () => true }) → { next: 'fixer'|'review-diff'|'done', since, files, open: [{ code, severity, title, why }], newCritical, critical, warning, paragraph }`; CLI `turbo-run jobs <N> review [--json]` (adds `next: 'fallback'` with `why`).

Decision table of `leanReviewNext` (findings from `reviewFindings`; info never counts):
1. `fixedAfterReview` → `review-diff`; `open` = each critical/warning finding of `review` that the fix report skipped (`skipped by the fixer`), lists as fixed with no commit, an unknown commit or only commits whose files are all Markdown or under `.planning/` and include none of the finding's files (`closed without a code change`), or does not name (`not in the fix report`); `files` = sorted unique `changedCode` ∪ the open findings' files, filtered by `exists`; no files → `done`.
2. else `changedCode` not empty → `review-diff`, `open` = every current critical/warning finding (`not re-checked since the code changed`).
3. else `diffReview` → `newCritical` = critical findings whose flattened lower-case title is not among `previousReview`'s titles; `fixer` when above 0, else `done`.
4. else `fixer` when `critical + warning` above 0, else `done`.

CLI facts: REVIEW.md `rel`, REVIEW-FIX.md = `rel` with `-REVIEW.md` → `-REVIEW-FIX.md`. `fallback` (why named) when REVIEW.md has no commit or `git status --porcelain` lists it, or REVIEW-FIX.md exists and has no commit or is listed. `r`, `f` = their last commits; `fixedAfterReview` = `f` ≠ `r` and `r` is an ancestor of `f`; `diffReview` = `f` exists and not `fixedAfterReview`; `previousReview` = `git show <f>:<rel>`; `changedCode` = `changedSince(git, r).code`; `commitFiles(sha)` = `git diff-tree --no-commit-id --name-only -r -z <sha>`, `null` on error. No REVIEW.md → `done`, counts 0.

## Planner decisions

1. Lean is pinned per phase at `--done gates-off` (`run/lean-p<N>.json`); a phase whose execution began without a pin (gates-off done or a SUMMARY: L1's boundary rule, so GSD's keys and turbo's steps switch together) finishes stage-5 (D10, the owner's phase 33).
2. `phase-step N` (and `--prep`) announce lean by a first line `lean: on`; the `phase N: next …` line stays last (M's step labels and `lines.at(-1)` tests keep working); `--json` is unchanged.
3. Lean decisions are new kinds of the L2-owned `jobs` command (`research`, `regate`, `review`); no new top-level command (`turbo-run lean` is L1's).
4. L2 tests inject the verdicts (`deps.signals`) and never depend on L1's heuristics; L1's real functions are the defaults.
5. "Critical/high" for code review = GSD's critical tier (CR-/BL-): GSD has no high tier; warnings left after the loop go to the note. Security is covered already: the auditor rejects documentation as evidence and the lane never chooses Accept.
6. "Closed by documentation alone" = no commit, an unknown commit, or commits touching only Markdown or `.planning/` files and none of the finding's files.
7. Open findings ride in the diff review's paragraph, so REVIEW.md stays the one record of what is open; no extra state file.
8. "New critical" = a critical title the reviewed version (REVIEW.md at the fix report's commit) did not have.
9. The loop's state comes from git's commit order of REVIEW.md and REVIEW-FIX.md (resume-safe); an uncommitted or dirty report (e.g. `commit_docs: false`) falls back to the stage-5 loop.
10. Gate input files: code = every path outside `.planning/`; security also the phase's PLAN and SUMMARY files, Nyquist its PLAN files, UI review its UI-SPEC; a gate without a committed report re-runs.
11. Re-gate replaces final-gate point 1's re-run and **Stale report** route `full`; gap-closure executions (`--gaps-only`) stay GSD runs (they execute plans; under lean only code review, regression and verifier remain in them).
12. Re-gate's code review carries no old findings (an owner-accepted one would loop); its critical findings or open threats stop for the owner.
13. A security gate GSD still runs (the owner turned `workflow.security_enforcement` back on) stays stage-5; the direct audit is `secure-phase.md` run without its enforcement check, so SECURITY.md keeps GSD's format and `outcome`/close read it unchanged.
14. The test deferral window = an active turbo-phase run (a progress file) of a lean phase until final-gate is done; `max_targeted` and the phase-end rule are off inside it; the UAT gap round and integrate keep `TURBO_FULL=1` (code changed after the final run).
15. "Big code block" = more than 10 lines.
16. The records commit holds answers, STATE.md, STATE-ARCHIVE.md (L1's budget trim) and `turbo-base.json`; gates off/restore and artifact commits stay their own (executors read the committed config; bases must follow their artifacts' commit).
17. Lean text lives in one `## Lean mode` section plus `**Lean:**` lines (stripped = stage-5, budget 9000 bytes); inserts go right before the Temporary files paragraph.
18. L1 interfaces are stubbed in one commit (default `enabled: true`, as L1), dropped at integration.
