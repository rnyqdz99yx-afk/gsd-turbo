# Stage 6 M — measurement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `turbo-run cost <N>` tells how much time and how many tokens phase N took, by step and role, for both phase
paths, and the supervisor logs one cost line per closed phase. **Architecture:** one new module `lib/cost.mjs` with two
sources merged into one cost object — path B: `run/cost-p<N>.json`, appended to by `recordSessionUsage`; path L: the
phase's lane sessions (job ids from `supervisor.log`, located through turbo's transcript layer `lib/transcripts.mjs`)
and their subagents, every API call and time gap attributed to a (step, role). The CLI and the log line render it; the
supervisor starts a detached `turbo-run cost N --log` at its two `phase N done` points. **Tech Stack:** Node.js ≥ 20
ESM, node:test, git, Claude Code CLI
**Spec:** docs/specs/2026-10-17-stage-6-lean-design.md (§7, §5.6 item 4, §6.2 last sentence, §6.11 item 3, §9 row M)

## Global Constraints

- Zero-dependency Node ESM; tests with `node --test` on targeted files only; CI Ubuntu/Node 22 + Windows/Node 24.
- IEU = input ×1 + cache write ×1.25 + cache read ×0.1 + output ×5 (spec §7).
- Idle gaps capped at 5 min (recon-tokens §1, "busy h").
- Path B store: `.planning/turbo/run/cost-p<N>.json` (spec §7).
- Table: step | role | sessions | time | out | in+create | cache read | ≈IEU, plus totals (spec §7).
- CLI: `turbo-run cost <N> [--compare <M>] [--json]` (spec §7).
- supervisor.log line at phase close: path, time, IEU, sessions, slices, fix rounds (spec §7); time and tokens by step (§5.6 item 4).
- Binding: `recordSessionUsage(runDir, phase, { step, role, sessionId, usage, wallMs })`; `phaseCost({ root, phase })` → `{ rows: [{ step, role, sessions, wallMs, out, inCreate, cacheRead, ieu }], total }`; `costLine(cost, { path })`.
- B1's usage shape: `{ input_tokens, cache_creation_input_tokens, cache_read_input_tokens, output_tokens }`.
- Transcripts live under `CLAUDE_CONFIG_DIR`, else `~/.claude` (`lib/paths.mjs` `claudeHome`); never real transcripts in the repo.
- M owns `lib/cost.mjs` and the `cost` command; `bin/turbo-run.mjs` gets only M's own lines.
- Release v0.5.0 together with L1 and L2 (spec §9).
- Commits: conventional, English, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Double counting.** Claude Code writes one JSONL line per content block, each with the message's full usage, and a
   woken lane's new transcript repeats the earlier history: every API call counts once (by `message.id`), every user
   entry once (by `uuid`), across all files of the phase. Pinned: Task 3 `phaseCost of a lane phase…` (fixture holds
   both cases; exact totals).
2. **Step attribution.** Only a `phase-step` Bash result relabels (a Read result quoting `phase 3: next uat` does not);
   a subagent takes the step of its dispatch through `meta.toolUseId`, a nested one through its parent agent even when
   listed first, an unlinked one reads `?`; `<synthetic>` messages count nothing. Pinned: both Task 3 phaseCost tests.
3. **Wall clock.** A gap counts at most 5 min; a gap that ends at a main-thread prompt (a wake, the owner) does not count;
   a harness task notification is not a prompt; rows are per transcript (parallel agents add up), total and steps are
   the merged timeline. Pinned: Task 3 (rows 30/385/20/180 s, total 616 s, step discuss 566 s); Task 1 for path B
   (union 1 020 000 ms against a row sum of 1 320 000 ms).
4. **Finding the phase's sessions.** Job ids only from `launch|adopt phase N` and `launch|adopt lane prep-N` (not
   `phase 30`, `3.1`, annotate or wake lines); the resumed transcript through the job state; every main's subagents;
   all under a non-default `CLAUDE_CONFIG_DIR`. Pinned: Task 2 `laneJobIds…`, Task 3 `laneTranscripts…` and
   `phaseCost reads the transcripts under CLAUDE_CONFIG_DIR`.
5. **The supervisor never blocks or dies on measuring.** It starts a detached child; a spawn failure (`'error'` event)
   is logged, never thrown; a throwing `deps.phaseCost` is logged and the done flow goes on, in checkout and in slots
   mode. Pinned: Task 5 tests.

## Planner decisions

1. ≈IEU weighs every cache write ×1.25; the recon weighed the 1h part ×2. B1's usage shape has no 1h split, and the A/B
   rule compares the two paths, so one scale (the spec's) for both.
2. A phase's lane sessions = job ids of `launch|adopt phase N` and `launch|adopt lane prep-N` in `supervisor.log` (the
   only record of every launch; supervisor.json keeps the last one), then `laneTranscript`/`laneSessionIds`/
   `sessionTranscripts`/`agentIndex` — no discovery of its own. Prep lanes count: lookahead 1 (D6) does the phase's
   discuss there.
3. Main-thread step = the last `phase-step` step (only from Bash calls with `phase-step`; `none` keeps the step), else
   the last gsd-/turbo- Skill or slash command, else `-`; no `/clear` rule (lanes never clear).
4. Dedupe by `message.id` and `uuid` across all files of a phase; mains in ascending mtime, so the original transcript
   owns its history and a woken lane's later transcript only its new part.
5. A prompt (gap not counted) is a main-thread user entry with text, no tool result, no harness notification, not
   meta/compact, starting with `<command-name>` or with neither `<` nor `[`; subagent prompts never count as waits.
6. Row time = per-transcript busy time; total and steps = merged wall clock (lane) or the union of session intervals
   (build); mixed sources add.
7. `sessions` = transcripts with a counted call (a woken lane's later transcript counts again); build: distinct
   sessionId.
8. `slices` = the phase's PLAN files (both paths); `fix rounds` = `attempts.fix` (lane) or `fixer` sessions (build).
9. The log line also carries `steps:` (time and ≈IEU per step, spec §5.6 item 4): transcripts vanish after ~30 days,
   the log stays.
10. The supervisor never measures inside a tick: a detached `turbo-run cost N --log` (`spawnCostLog`), cwd in turbo's
    own directory, `'error'` logged; hooked at both `phase N done` points (`finishLane`, `dropLane` done).
11. `cost-p<N>.json` = `{ v: 1, phase, sessions: [...] }`; a file that does not parse counts as empty; invalid input →
    `TypeError` naming the field; synchronous, one writer per phase.
12. `phaseCost` also returns `phase`, `steps`, `sources`, `slices`, `fixRounds` and takes an optional `env`.
13. `--compare` shows sessions, time and ≈IEU of both phases and the N/M ratio; the A/B across two copies uses
    `cost N --json` in each copy (no cross-project compare).
14. `runCostCommand` parses its own flags; bin's `VALUE_FLAGS` is not touched.
